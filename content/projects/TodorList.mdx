在这里有一个小知识点，是自己摸索出来的

每个DOM结点的事件绑定的函数，在挂载完成之后，函数里面的所有变量都会变成常量，所以DOM结点在页面上执行的函数都是确定好的。

比如在list组件里面，我们按照todos来遍历渲染item，所以item里面的每一个li都其实是对应一个todo对象，只要挂在到浏览器上，那么li所对应的对象就不变，除非重新挂载。

给props添加限制

目前我们的代码，所有变量或者方法等等都没有加任何限制，也就是说不管是子传父还是父传子，亦或者是函数调用，默认都是任何情况都接受，但是这样往往会在实际运行中出现大量问题。比如在传递的参数是null的情况下依旧执行null.方法(),或者是默认传递3个参数，但是实际上只传了2个参数，第3个参数就自动默认为undefined，那么就会导致页面渲染有问题，甚至白屏等等的危险。

因此，我们需要给我们的代码添加上规范的限制，也就是代码规范化。在这里我用的是typescript，也可以用prop-types，我列一下它们的区别：




| **特性**   | **prop-types (JS)**                 | **TypeScript (TS)**                                      |
| ---------- | ----------------------------------- | -------------------------------------------------------- |
| 定义位置   | 通常在组件函数外部赋值              | 通常在组件函数外部定义 interface，或在内部内联定义        |
| 必填/选填  | `.isRequired` 后缀表示必填          | 属性名后加 `?` 表示选填，不加默认为必填                   |
| 字符串     | `PropTypes.string`                  | `string` (小写关键字)                                    |
| 数字       | `PropTypes.number`                  | `number` (小写关键字)                                    |
| 布尔值     | `PropTypes.bool`                    | `boolean`                                                |
| 数组       | `PropTypes.arrayOf(PropTypes.string)` | `string[]` 或 `Array<string>`                          |
| 对象       | `PropTypes.shape({ ... })`          | `{ key: type }`                                          |
| 联合类型   | `PropTypes.oneOfType([...])`        | `type \| otherType` (如 `string \| number`)              |
| 自定义验证 | 需要写一个返回 Error 的函数         | 直接使用 `type` 或 `interface` 组合                       |

 

如果你要用prop-types的话就需要在控制台中执行下面的命令，将prop-types下载下来，这个体积很小下载也快，然后在用

`import PropTypes from 'prop-types';` 就可以了，详细的语法我就不介绍了，感兴趣的朋友可以去官网搜索一下[道具类型 - NPM](https://www.npmjs.com/package/prop-types)。不过近几年，prop-types很少被使用了。

然后在list组件中，我们一定要给props做一个定义，props是一个对象，对象里面就是我们从其他组件接收的参数，要对每一个参数进行一个定义，注意：函数的定义是，函数名: (参数名: 参数类型, ...) => 返回值类型,其他的定义和前面说的一样。

定义好props，我们就需要在component使用泛型：

`extends Component<ItemProps, {}>`

Component 是 React 提供的基类，它接受两个类型参数：

第一个参数 `<ItemProps>`：定义 Props（属性） 的类型。

这意味着：在这个组件内部，this.props 的类型被锁定为 ItemProps。

好处：当输入 this.props. 时，VS Code 会自动提示 updateTodo、deleteTodo 和 todo。如果尝试访问不存在的属性（如 this.props.name），TS 会直接报错。

第二个参数 `<{}>`：定义 State（状态） 的类型。

`{}` 表示一个空对象，意味着这个组件没有内部状态（即不使用 this.state 或 this.setState）。

如果组件有状态，比如 `{ count: number }`，这里就会写成 `Component<ItemProps, { count: number }>`。
